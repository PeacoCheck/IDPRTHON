# UI-аудит и принятая архитектура

Исходный интерфейс был перегружен несколькими уровнями навигации и не давал
ясного пути от объекта к конкретному акту. Рабочая модель перестроена вокруг
одного потока:

```text
объект → реестр → группа/узел → документ → выпуск
```

## Что реализовано

- Стартовый экран — реестр объектов, а не технический dashboard.
- В объекте первым открыт реестр; рядом только проверка и карточка реквизитов.
- Один контекстный список групп вместо дублирующих sidebar/деревьев.
- Любой документ открывается напрямую из группы или глобального поиска.
- Создание документа показывает автополя и ручные поля до появления черновика.
- Импортированный файл остаётся оригиналом; сформированный документ имеет
  отдельную ссылку на DOCX.
- Проверка структуры различает отсутствие и незавершённый документ.
- Исключение содержит тип решения, причину, автора, дату и подтверждение.

## Эталон объекта

Эталон выведен из 17 объектов локального корпуса: реестр, проектная/рабочая,
разрешительная, журналы, акты, схемы, материалы/паспорта, ППР/дефектные,
подтверждения и архив версий. Реальные пропуски корпуса не считаются
юридической нормой.

## Визуальное решение

Светлая нейтральная система в духе спокойных продуктовых интерфейсов Apple и
Google: системный шрифт, мягкий синий акцент, белые поверхности, небольшие
радиусы и короткий motion. Смысловые статусы сохраняют подписи и иконки.
