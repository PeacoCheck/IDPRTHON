# ID Vault

ID Vault — локальный архив исполнительной документации для строительных объектов. Приложение связывает каждый файл с конкретным объектом и группой, хранит версии, показывает рабочий статус документа и сравнивает фактический архив с эталонной структурой.

Основной путь в интерфейсе:

```text
объект → реестр → группа → документ → предпросмотр или правка статуса
```

## Что умеет приложение

- вести активные и архивные объекты с отдельными карточками и файловыми реестрами;
- загружать документы в нужную группу, искать их и открывать прямо из реестра;
- отдельно показывать наличие файла и состояние работы: ожидается, в работе, готов, требует правок;
- просматривать PDF, изображения, DOCX и XLSX локально, без отправки рабочих файлов в облако;
- хранить предыдущие версии при замене файла;
- использовать библиотеку оригиналов шаблонов и копировать готовый файл в выбранный объект;
- проверять комплектность объекта, фиксировать пропуски, эквиваленты и обоснованные исключения;
- показывать сводный отчёт о комплектности всех объектов по адресу `http://127.0.0.1:8765/#/reports/completeness`;
- добавлять собственные группы и ожидаемые документы.

## Структура нового объекта

По умолчанию объект получает следующие группы:

- Реестр;
- Проектная и рабочая документация;
- Разрешительная документация;
- Журналы;
- Акты и испытания;
- Исполнительные схемы;
- Материалы и паспорта;
- ППР, графики и дефектные;
- Фото и подтверждения;
- Архив заменённых версий;
- Прочее.

Структура не жёсткая: пользователь может добавлять группы под конкретный котёл, трубопровод, насос, фильтр или другой узел.

## Проверка комплектности

Проверка сравнивает документы объекта с набором ожидаемых требований. Отсутствие файла и незавершённый рабочий статус — разные состояния и считаются отдельно.

Пропуск нельзя закрыть без причины. Для обоснованного исключения сохраняется пояснение, а для замены эквивалентом — ссылка или другое подтверждение. Сайт [Ispolnitelnaya.ru](https://ispolnitelnaya.ru/) используется только как справочная библиотека форм и примеров, а не как нормативная истина.

## Шаблоны

Шаблон считается готовым к использованию только после загрузки исходного файла. Пустой шаблон явно помечается «НЕТ ФАЙЛА» и не может быть добавлен в объект. В базовом наборе первым идёт реальный DOCX общего журнала работ; остальные типы можно дополнить своими проверенными файлами.

ID Vault не меняет содержимое оригинала: при добавлении шаблона в объект создаётся независимая копия файла в его архиве.

## Быстрый запуск в Windows

Требуются Python 3.12+ и Node.js 22+.

1. Запустите `ЗАПУСК.bat` двойным щелчком.
2. Дождитесь сборки и запуска сервера.
3. Если браузер не открылся автоматически, откройте `http://127.0.0.1:8765/`.

В репозитории один штатный launcher. Параметры приложения можно передать ему из PowerShell:

```powershell
.\ЗАПУСК.bat --no-browser
.\ЗАПУСК.bat --port 8770
```

Приложение слушает только локальный адрес. База SQLite, импортированные документы, их версии и пользовательские файлы шаблонов находятся в каталоге `vault/`; он исключён из Git. Для резервного копирования достаточно остановить приложение и скопировать этот каталог целиком.

## Ручной запуск

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Set-Location frontend
npm install
npm run build
Set-Location ..
.\.venv\Scripts\python.exe app.py --no-browser
```

## Стек и зависимости

- backend: Python 3.12, FastAPI, Uvicorn, SQLAlchemy/SQLite, Pydantic, Alembic, python-multipart, python-docx, docxtpl, openpyxl и pypdf;
- frontend: Vite, ES-модули, Idiomorph, AutoAnimate, docx-preview, Chart.js, Lucide и локальные Fontsource-шрифты.

Точные версии backend зафиксированы в `requirements.txt`, frontend — в `frontend/package.json` и `frontend/package-lock.json`.

## Проверка

```powershell
Set-Location frontend
npm run build
Set-Location ..
.\.venv\Scripts\python.exe -m unittest -v backend.tests.test_docx_templates backend.tests.test_file_archive_api tests.test_backend_api
.\.venv\Scripts\python.exe -m compileall -q backend tests
```

## Структура репозитория

- `backend/` — FastAPI API, SQLite, импорт, версии, предпросмотр и проверка комплектности;
- `frontend/` — локально собираемый интерфейс на Vite и ES-модулях;
- `resources/templates/` — исходные файлы библиотеки шаблонов;
- `tests/` и `backend/tests/` — автоматические проверки API, шаблонов и файлового архива;
- `vault/` — локальные рабочие данные пользователя, не публикуются в репозитории.
